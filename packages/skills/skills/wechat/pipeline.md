# 工程公众号流水线（MVP）

一条最小闭环：选题确认 → 正文 → 标题 → 排版。不做第三方「爆款榜」抓取（数据源脆、证书校验也关着，默认跳过）。


## Vault 落点（W2）

| 产物 | vault 路径 |
|---|---|
| Brief | `10-卡片盒/公众号/briefs/` |
| 成稿 | `10-卡片盒/公众号/drafts/` |
| 标题 / 审校 | `10-卡片盒/公众号/review/` |
| 排版 HTML | `90-附件/公众号/layout/`（**仅桌面本地工具写入**；模型不得直写 `90-附件/`） |

禁止双写 `/workspace/content-team`。笔记改动走 proposal → Apply。成品**禁止** `【待补】`；缺材料改为公开可核验事实或标明「假设」。


## 何时用

用户说「按流水线写一篇」「工程号日更流程」「从素材到可粘贴公众号」等。

## 步骤

1. **收输入**  
   主题 / 素材 / 大纲 / 草稿；读者是谁；篇幅长文还是短文；有无硬性不能写的点。

2. **跑写作**  
   按 [工程公众号写作](sand-workflow:工程公众号写作)（若 id 不同以实际 skill id 为准）产出 Markdown 正文。  
   若技能库里的 id 是 slug，用已保存的写作 skill。

3. **人审一拍**  
   把正文交给用户看结构与观点；用户没说「继续」前，不起标题、不排版。  
   （若用户明确说「一口气出到可粘贴」，可跳过等待，但要标明哪些是待填 `xxx`。）

4. **起标题**  
   用工程公众号标题 skill，输出候选表 + 推荐。

5. **排版**  
   用户选定标题后，用工程公众号排版 skill 由本地工具生成 `90-附件/公众号/layout/{slug}/index.html`。

6. **交付清单**
   - 正文 Markdown
   - 选定标题 + 备选 2 个
   - 预览 HTML 路径与复制说明
   - 建议配图点（可选，不强制出图）
   - 明确未做：爆款数据探测、自动发布、封面生成（需要时另开）

## 选题启发（无爆款 API 时的替代）

用公开可核验来源，不要编造阅读量：

- 用户自己的本周踩坑 / PR / 线上事故
- GitHub/官方 changelog、RFC、复盘帖
- 自己产品或团队的真实前后对比

输出 3 个候选角度，让用户挑 1 个再写。

## 不要做的事

- 调用不明第三方微信热榜 API，或关闭 TLS 校验去抓数
- 承诺「爆文 / 10 万+」
- 自动群发到公众号后台（除非用户另接官方流程且明确授权）
